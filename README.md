# Gift Price Parser — TypeScript · NestJS · React · WebSocket · PostgreSQL

Поиск **реальной цены** апгрейд-подарка Telegram: выбираешь коллекцию (и модель/фон/символ) —
получаешь историю сделок сразу с пяти площадок, медиану, средние без выбросов, текущие флоры,
цену в TON, USDT и звёздах, график с карточкой подарка и живые обновления по WebSocket.

```
server/                  NestJS + TypeORM: площадки, каталог, курс, поиск, WebSocket
web/                     React + Vite: интерфейс
docker-compose.yml       PostgreSQL 16
legacy-python/           прежняя реализация на Python (Tkinter) — как справочник
data.json                каталог коллекций (общий с main.py)
ton_usd.json             курс TON по дням за 2 года
downloaded_collections/  картинки моделей и символов
```

## Площадки

| Источник | История сделок | Активные лоты | Вход в Telegram | Как получаем |
|----------|----------------|---------------|-----------------|--------------|
| **MRKT** | да, вся лента | да | нужен | `api.tgmrkt.io` — `POST /api/v1/feed` |
| **Portals** | да, вся лента | да (публично) | нужен для истории | `portal-market.com/api/market/actions/` |
| **Fragment** | до 60 сделок | да | не нужен | HTML `fragment.com/gifts/<slug>?filter=sold` |
| **Telegram** | нет (API не отдаёт) | да + оценка Telegram | нужен | MTProto `payments.getResaleStarGifts` |
| **Tonnel** | да, вся история | да | нужен | `gifts3.tonnel.network` — `POST /api/saleHistory` |

Все роуты и форматы описаны в [legacy-python/API.md](legacy-python/API.md).

## Запуск

Нужен **запущенный Docker Desktop** (в нём поднимается PostgreSQL) и Node 22.5+.
Всё остальное — две команды из корня проекта:

```bash
npm run setup
```

```bash
npm run dev
```

Интерфейс — http://localhost:5173, API и WebSocket — http://localhost:3000.

`npm run setup` = установка зависимостей обоих пакетов (npm workspaces) + `docker compose up -d`
+ `npm run seed` + `npm run import-session`. Повторно запускать не нужно, дальше только `npm run dev`.

`seed` переносит в Postgres то, что уже собрано: 120 коллекций, 41 024 атрибута
(модели, фоны с цветами, символы) и 730 дней курса TON.
`import-session` переносит существующую сессию Telethon (`tg_session.session`) в базу —
заново логиниться не нужно; если файла нет, шаг просто пропускается, а вход делается через API:
`POST /api/auth/telegram/start` с номером, затем `/confirm` с кодом (и паролем 2FA) —
код приходит в Telegram и вводишь его ты сам.

### Если что-то не запускается

```bash
npm run doctor
```

Проверяет версию Node, ключи в `.env`, зависимости, Docker, доступность Postgres,
наличие данных в базе и занятые порты — и пишет, что именно сделать.

Частые случаи:

* **`failed to connect to the docker API` / `PostgreSQL не отвечает`** — не запущен Docker Desktop.
  Открой его, дождись зелёного статуса, потом `npm run db:up`.
* **Своя база вместо Docker** — пропиши `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`
  в `.env` (см. `server/.env.example`), тогда Docker не нужен.
* **Порт 3000 или 5173 занят** — закрой прошлый запуск или поменяй `PORT` в `.env`.

## Как это устроено

**Поиск (`server/src/search`)** — сессия живёт в памяти, данные в Postgres:

1. при создании сессии сразу отдаются сделки, уже накопленные в базе — таблица рисуется мгновенно;
2. дальше все площадки опрашиваются **параллельно**, и каждая пачка сделок уходит во фронт
   сразу, как пришла: первые данные видно через ~0,3 с, все пять площадок — за 1,5 с;
3. приоритет у свежего: с каждой площадки берётся первая (самая новая) страница,
   следующие — только по мере прокрутки таблицы;
4. каждые 20 секунд подтягиваются новые сделки, раз в минуту — флоры;
5. всё новое улетает во фронт по WebSocket (`trades:new` с именем площадки,
   `floors:update`, `search:progress`, `search:done`);
6. новый поиск отменяет предыдущий: старая сессия закрывается вместе со своими
   генераторами, её события больше не приходят.

**Поиск по ссылке** — вставь `https://t.me/nft/HeroicHelmet-1349` (или `fragment.com/gift/…`,
или просто `HeroicHelmet-1349`): бэкенд достаёт модель, фон и символ этого экземпляра
через `payments.getUniqueStarGift`, а без входа в Telegram — со страницы Fragment.
Дальше ищутся точные копии; какие атрибуты считать «точной копией», выбирается галочками
(по умолчанию модель + фон). Сам экземпляр подсвечивается: в таблице строка обводится
белым, на графике точка получает белый кружок и подпись с номером подарка сверху.

**Ценовой диапазон** — поля «от» и «до» в TON (пустое = без границы). Диапазон
применяется сразу ко всему: к истории сделок, к статистике, к флору и к витрине лотов.
Там, где площадка умеет фильтровать по цене сама (MRKT, Portals, Tonnel), фильтр уходит
в запрос, остальное отсекается на нашей стороне — поэтому ни один лот мимо диапазона не
проскочит. Пока диапазон включён, над таблицей висит плашка с кнопкой «сбросить»:
медиана считается только по попавшим в него сделкам, и об этом лучше помнить.

**Вкладка «В продаже»** — активные лоты со всех площадок одним списком, от дешёвых к
дорогим: площадка, модель, фон, символ, номер и цена в TON, долларах и звёздах. Двойной
клик открывает подарок в Telegram. Витрина отдаётся постранично, и с заданным диапазоном
лотов берётся до 100 с площадки — иначе было бы видно только два десятка самых дешёвых.
Цена лота считается по сегодняшнему курсу TON (платить-то сегодня), а сделки — по курсу
на свою дату.

Так выглядит поиск «Jingle Bells, 70–90 TON»: 35 сделок в диапазоне и 114 лотов, среди
которых `JingleBells-86952` за 81,6 TON — тот самый экземпляр по ссылке.

**Как устроен скрапинг по времени.** Порядок такой:

| шаг | что происходит | когда видно |
|-----|----------------|-------------|
| 0 | ответ из Postgres — всё, что уже накопил сканер и прошлые поиски | мгновенно, ~50 мс |
| 1 | параллельно стартуют все площадки: первая (самая свежая) страница по 15 сделок + активные лоты | — |
| 2 | каждая площадка, как ответила, тут же шлёт свою пачку по WebSocket | MRKT ≈ 0,1 с, Tonnel и Fragment ≈ 0,2 с, Telegram ≈ 0,5 с |
| 3 | Portals отвечает медленнее из-за своего кеша | 0,5 с на «тёплой» коллекции, до 12 с на «холодной» |
| 4 | прокрутка таблицы — следующая страница со всех площадок, снова параллельно | по требованию |
| 5 | live-цикл: раз в 20 с свежие сделки, раз в минуту флоры | фоном |

Ускорение держится на четырёх вещах: параллельность между площадками, маленькая первая
страница, keep-alive соединения (не переустанавливаем TLS на каждый запрос) и общий кеш
в Postgres, который непрерывно пополняет фоновый сканер.

**Ограничитель запросов** (`server/src/markets/rate-limiter.ts`) — у каждой площадки своя
«полоса»: максимум одновременных запросов и минимальная пауза между ними (например, MRKT —
3 запроса и 100 мс, Portals — 2 и 250 мс, Telegram — 1 и 250 мс). Через неё проходят и поиск,
и фоновый сканер, поэтому они делят канал и не ловят 429; на 429 площадка автоматически
уходит в паузу на несколько секунд.

**Снимок цен всего рынка** (`server/src/scanner/floors.service.ts`) — обходить коллекции по
одной долго, а весь рынок помещается в полтора десятка запросов: у MRKT список коллекций
сразу с флором, у Portals — список коллекций и роут атрибутов, который принимает по десять
коллекций за раз и возвращает флор каждой модели и каждого фона. Полный снимок — около
16 000 строк (249 коллекций, 7 500 моделей, 8 400 фонов) за 13–20 секунд, обновляется раз
в 5 минут. Символы не берём: на цену они почти не влияют.

**Сканер выгодных** (`server/src/scanner`) работает по этому снимку — одним SQL, без единого
обращения к площадкам. Сравнивается не с медианой продаж, а со **скользящей средней самого
флора**: флор — это минимум предложения, медиана — середина сделок, поэтому «флор ниже
медианы» верно почти всегда и находкой не является. А вот флор, упавший относительно
собственной недавней истории, — это ровно то, что нужно: кто-то только что выставил дёшево,
и это можно купить. Медиана продаж остаётся страховкой: если по позиции есть история за 90
дней, цена не должна быть заметно выше неё.

Второй цикл — прежний обход истории по кругу, но у него теперь другая работа: копить сделки
в `trades`, из которых считаются медианы. Его находки помечаются «продано» (это уже
состоявшиеся покупки), находки по флорам — «в продаже». Всё новое сразу уходит во фронт
событием `deals:new`.
Клик по карточке открывает эту находку в обычном поиске с подсветкой экземпляра.
Чипы площадок над лентой фильтруют и её, и сам обход (список уходит в сканер), а сделки
сортируются по времени или по размеру скидки. Ценовой диапазон над лентой оставляет
только находки нужной стоимости — «выгодные подарки за 70-90 TON»; сам обход он не
сужает, иначе медианы считались бы по обрезанной выборке.

**Что не считается продажей.** Розыгрыши (lucky buy) на MRKT и Portals приходят в ленте
рядом с обычными сделками, но их `amount` — цена билета, а не подарка: Xmas Stocking
уходил там за 0,0444 TON при медиане 3,9. Такие события помечаются `kind: 'lucky_buy'` и
не попадают ни в график, ни в медианы, ни в ленту выгодных — иначе там оседали бы
«скидки» по −99 %. Дополнительно сканер отбрасывает всё, что дешевле медианы более чем
на 90 %.

Каждая сделка кладётся в `trades` с ключом дедупликации, поэтому база постепенно
накапливает историю и повторные поиски открываются мгновенно.

**График (`web/src/components/PriceChart.tsx`)** — управление как в TradingView:

| действие | что делает |
|----------|------------|
| тащить по полю графика | свободное перемещение по времени и цене |
| тащить по шкале цен (справа) | сжать/растянуть вертикаль |
| тащить по шкале времени (снизу) | сжать/растянуть горизонталь |
| колесо | зум по времени вокруг курсора |
| shift + колесо | сдвиг влево/вправо |
| двойной клик или кнопка «сброс» | вернуться ко всем сделкам |

Наведение на точку показывает карточку: картинка на своём фоне, название, модель,
площадка и цена в TON, USDT и звёздах; у края экрана карточка переворачивается,
чтобы не вылезать за границы.

**Курс и звёзды (`server/src/rates`)** — цена TON по дням: длинный хвост с Binance,
свежие 365 дней с CoinGecko, недостающие даты догружаются точечно. Каждая сделка считается
**по курсу на свою дату**, поэтому старые сделки видно честно. Звёзды: в основном поле —
сколько звёзд нужно купить (1 ★ = $0,0150), в карточке подарка второй строкой — сколько
получит продавец (1 ★ = $0,0118).

**Telegram (`server/src/telegram`)** — MTProto через `teleproto`: сессия хранится в Postgres
(`settings`), initData для мини-аппов MRKT / Portals / Tonnel выпускается автоматически и
кешируется на 40 минут, официальный маркет читается через `payments.*`.

**Особенности площадок, которые пришлось учесть:**

* MRKT после `/auth` ставит cookie `access_token` и без неё отвечает 401 — у HTTP-клиента
  есть cookie-jar (в Python это делал `requests.Session`).
* Tonnel закрыт Cloudflare для обычных HTTP/1.1-клиентов Node (axios, undici, curl → 403
  «Just a moment…»). Проходит HTTP/2 с браузерным набором шифров **и порядком заголовков**
  `content-* → user-agent/origin/referer → accept*` — это `server/src/markets/http2.ts`.
* Fragment ищет только по одному атрибуту: если задать и модель, и фон, источник пропускается
  с пометкой (иначе в статистику попали бы чужие сделки).
* Официальный маркет Telegram истории сделок не отдаёт — только лоты и оценку
  (в валюте аккаунта).
* Portals кеширует историю на своей стороне: первый («холодный») запрос по коллекции
  может висеть десятки секунд. Поэтому на страницу истории даётся 12 секунд без повтора —
  остальные площадки не ждут, а Portals подтянется на следующей прокрутке или live-тике.

## API

| Метод | Роут | Что делает |
|-------|------|------------|
| GET | `/api/sources` | список площадок и их возможности |
| GET | `/api/catalog/collections?q=` | поиск коллекций (по любому слову) |
| GET | `/api/catalog/attributes?collection=&kind=&q=` | модели / фоны / символы с флором |
| POST | `/api/catalog/refresh` | обновить каталог с Portals |
| GET | `/images/:short/:file.png` | картинка модели (недостающие докачиваются) |
| GET · POST | `/api/rates` · `/api/rates/refresh` | курс TON и цены звёзд |
| POST | `/api/search` | создать сессию поиска (в теле в том числе `minPrice` / `maxPrice`) |
| POST | `/api/search/:id/more` | следующая страница истории |
| POST | `/api/search/:id/refresh` | подтянуть новые сделки |
| DELETE | `/api/search/:id` | остановить поиск |
| GET | `/api/gift?url=…` | подарок по ссылке: модель, фон, символ |
| GET | `/api/deals?minDiscount=&hours=&markets=&sort=&minPrice=&maxPrice=` | лента выгодных: порог, окно, площадки, сортировка (`time` / `discount`), диапазон цен |
| GET · POST | `/api/scanner` | статус и настройки фонового сканера |
| POST | `/api/scanner/scan` | проверить коллекцию прямо сейчас |
| GET | `/api/floors` | статус снимка цен: сколько строк и когда обновляли |
| POST | `/api/floors/refresh` | пересобрать снимок цен по всему рынку |
| POST | `/api/floors/scan` | пересчитать ленту по текущему снимку |
| GET · POST | `/api/auth/telegram/*` | статус, вход по коду, выход |

WebSocket (socket.io, тот же порт): `search:subscribe {sessionId}` → события
`trades:new` (с именем площадки), `floors:update`, `search:progress`, `search:done`.
Лента выгодных приходит всем подключённым событием `deals:new`.

## Схема Postgres

`collections`, `attributes` (модели/фоны/символы + цвета фонов), `trades` (история сделок
с уникальным ключом на площадку), `listings` (снимок активных лотов по одному поиску),
`floors` (минимальные цены по всему рынку: коллекция / модель / фон, с предыдущим значением
и скользящей средней), `deals` (находки сканера с опорной ценой и процентом), `ton_rates`
(курс по дням), `settings` (сессия Telegram и кеш initData).

## Как читать результат

* **Медиана** — главный ориентир: одна случайная сделка её не сдвинет.
* **Средняя без выбросов** — среднее после отсечения хвостов по правилу Тьюки (1.5·IQR).
* **Флор** — минимальная активная цена; медиана сделок — за сколько реально уходит.
* Цена зависит прежде всего от модели: ищи с указанной моделью, иначе смешаются
  лоты за 170 и за 900 TON.

## Прежняя версия

`legacy-python/` — рабочая реализация на Python с Tkinter-интерфейсом (`python run_gui.py`,
`python cli.py search ...`). Она читает те же `data.json`, `ton_usd.json` и картинки из корня,
так что обе версии живут рядом и не мешают друг другу.
